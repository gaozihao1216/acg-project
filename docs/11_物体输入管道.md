# 物体输入管道：一条命令从文件到惯量

> 实现：`Code/src/geom/meshio.py`（OBJ/STL/点云）、`Code/scripts/analyze_object.py`（命令）
> 测试：`python Code/tests/test_object_input.py`（11 项）

## 1. 直接回答

之前的状态是：**质量属性的计算已经做好，但没有任何文件入口，也没有命令**——
`from_mesh` / `from_points` 只在测试里被 Python 直接调用。现在补上了。

```bash
# 网格 → 全部质量属性 + 碰撞代理 + 可跑的场景
python Code/scripts/analyze_object.py bunny.obj --mass 2.5

# 用密度代替质量
python Code/scripts/analyze_object.py part.stl --density 1200

# 只有点云（任意分布，自动判断该不该加截断修正）
python Code/scripts/analyze_object.py --points cloud.csv --mass 3.0

# 顺手生成能直接被 run_sim.py 加载的场景
python Code/scripts/analyze_object.py bunny.obj --mass 2.5 --emit scene.json
```

输出三块：**质量属性**、**碰撞代理**、**场景片段**。

## 2. 三种信息、三个角色

「不规则物体的三个信息」这个划分是对的，而且它们在引擎里是**三个独立角色**：

| 角色 | 输入 | 用途 | 本管道 |
|---|---|---|---|
| **碰撞代理** | 点集 / 网格 | 生成接触（法向、穿透深度） | 自动求凸包 → `ConvexHullGeometry` |
| **质量分布** | 网格（散度定理）或点云 | 质心 + 完整惯量张量 | 两条路径 |
| **渲染外观** | 高精度网格 | 只给 Blender | 已支持（`_create_hull`） |

三者可以完全不来自同一个文件。一个空心花瓶可以是：碰撞=包围它的凸壳，
质量=只在薄壁处有点的点云，外观=高精度网格。

## 3. 两条质量属性路径

| 路径 | 方法 | 误差 | 前提 |
|---|---|---|---|
| `from_mesh` | 散度定理，剖分成有符号四面体 | **解析精确** | 网格闭合且缠绕一致 |
| `from_points` | 求和 `Σ mᵢ(\|xᵢ\|²1 − xᵢxᵢᵀ)` + 截断修正 | 取决于采样方式 | 任意点集 |

点云路径的修正项与它当前的问题，单独写在
`docs/12_点云截断修正的算法路径.md`。

**点云不能用来做碰撞**：没有表面就没有法向与穿透深度。碰撞几何必须另给网格。

```
      [ 0.0183333333    0.216666667              0]

```

**为什么同时打印完整张量和主惯量**：引擎内部只用对角值，但完整张量是物理事实。
报告里的"非对角占比"给出可判断的数字——1e-3 量级可以用对角近似，5.6% 就不行。

```
碰撞代理（凸包）
------------------------------------------------------------------------------
  面 / 棱         5 / 9
  凸包体积        0.33 m³（占本体 100.0%）
  SAT 候选轴      ≤ 5 + 5 + 9² = 91
  规模合适，可实时
  最低点（相对质心） -0.3 m  → 放在地面上时 position.z = 0.3
```

"最低点"这一行是给 `--emit` 用的：它保证生成的场景**不会以初始嵌入开始**
（引擎有一道初始穿透校验会直接拒绝这种场景）。

## 5. 三个解析器的坑

都属"算错了也不报错"的类型，所以每条都有专门的测试。

**OBJ 负索引。** `f -4 -3 -2` 指的是"当前已读入的 4 个顶点的倒数第 4/3/2 个"。
漏了它会读成完全不同的形状，体积还是个数字。同时要处理 `f a/b/c`、`f a//c`
和多边形面的扇形三角化。

**STL 二进制识别。** 不能看开头是不是 `solid`——**很多导出器在二进制 STL 的
80 字节头里就写着 `solid`**。唯一可靠的判据是

$$\text{文件大小} = 84 + 50 \times \text{三角形数}$$

测试专门构造了一个"头部写 solid 的二进制文件"来卡这条。

**STL 顶点去重。** 二进制 STL 每个三角形独立存 3 个顶点。不去重的话顶点数是
`3F` 而不是 `V`，**闭合性诊断直接失效**（每条边都是孤立的）。
测试：24 条顶点记录 → 去重后 6 个顶点。

## 7. 三种格式的一致性

同一个棱柱经 OBJ / ASCII STL / 二进制 STL 读出：

| 格式 | 顶点 | 面 | χ | 体积 | Ixx |
|---|---:|---:|---:|---|---|
| OBJ | 6 | 8 | 2 | 0.330000000000 | 0.291666666667 |
| ASCII STL | 6 | 8 | 2 | 0.330000000000 | 0.291666666667 |
| 二进制 STL | 6 | 8 | 2 | 0.330000020266 | 0.291666682561 |

最大差异 **2.03e-08** —— 这是二进制 STL 用 **float32** 存顶点的固有限制
（约 1e-7 精度），不是解析错误。
