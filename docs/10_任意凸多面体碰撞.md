# 任意凸多面体：凸包构造、质量属性、广义 SAT

> 实现：`Code/src/geom/convexhull.py`、`Code/src/physics/convex_sat.py`、
> `Code/src/geom/geometry.py`（`ConvexHullGeometry`）
> 测试：`python Code/tests/test_hull.py`（15 项）
> 演示：`Code/scenes/demo_hull.json` → `results/w3/demo_hull.mp4`

## 1. 输入模型：一堆点就够了

任意形状进入引擎只需要**一个点集**：

```
点集 --(凸包)--> 顶点表 + 多边形面表 --(散度定理)--> 体积/质心/完整惯量张量
```

场景 JSON 里就是：

```json
{"type": "hull", "points": [[x,y,z], ...]}
```

构造 `ConvexHullGeometry` 时做掉三件事，**缺任何一件都会导致"能跑但不对"**：

| 步骤 | 作用 | 漏掉的症状 |
|---|---|---|
| 质心平移到原点 | 刚体的 position 必须指质心 | 物体绕偏心的点转，"甩尾" |
| 旋转到惯量主轴系 | 引擎只存对角惯量 | 世界逆惯量错到 2–13 倍 |
| 重算面法向与棱表 | SAT 需要它们 | 分离轴缺失，物体互相穿过 |

## 2. 凸包：增量法 + 共面合并

标准增量算法：先找 4 个不共面的点构成初始四面体，然后逐点判断"能看见哪些面"，
用**地平线**（可见面与不可见面的交界边）连到新点。看不见任何面的点直接丢弃。

### 为什么必须合并共面三角形

增量法天然产生三角形。立方体 8 个顶点会得到 **12 个三角形**，但它们只落在 6 个平面上。
不合并的话 SAT 会把同一平面数三遍：

| | 面法向轴 | 棱数 | 棱-棱候选轴 |
|---|---:|---:|---:|
| 不合并 | 12 | 18 | 324 |
| **合并后** | **6** | **12** | **144** |

**慢 2.25 倍**，而且面法向重复会让"最小穿透轴"出现并列，法向选择不稳定。

合并做法：按 `(法向, 平面常数)` 分组，收集有向边——组内共享的内部边会同时以
正反两个方向出现、互相抵消，剩下的就是该多边形的边界环。

实测立方体：

```
体积 = 1.000000000000
顶点 = 8，面 = 6（全部四边形），棱 = 12
```

## 3. 主轴并入姿态：引擎一行没改

任意形状的惯量张量有非对角项，而引擎只存 `(Ixx, Iyy, Izz)`。做法是
**正交对角化**后把主轴旋转 Q 并进物体朝向：

$$I = Q\Lambda Q^{\mathsf T}\;\Longrightarrow\; I_{\text{world}} = (R_{\text{spec}}Q)\,\Lambda\,(R_{\text{spec}}Q)^{\mathsf T}$$

所以 `RigidBody.from_object_spec` 里只加了一行：

```python
orientation = quat.quat_multiply(spec.transform.orientation, geometry.inertia_frame())
```

顺序不能反——四元数乘法是"先施加右、再施加左"，写成这样才是**先转主轴、再按场景姿态摆放**。

### 两个方向相反、都必须用对的旋转

这里有一个极易搞混的地方，我第一版就混了：

- **顶点 → 主轴坐标**：`v' = Qᵀ v`（用 Q 的共轭）
- **姿态复合**：`R_final = R_spec · Q`（用 Q 本身）

两处都写 Qᵀ 的后果：顶点位置**看起来是对的**（顶点用了共轭，反射被抵消），
但世界逆惯量错到 2–13。那个"顶点对、惯量错"的组合现象正是定位线索。

### 一个隐藏很深的 bug：特征向量的左手系

Jacobi 求出的特征向量**符号是任意的**——$v$ 与 $-v$ 都是同一特征值的特征向量。
所以得到的基底有**约一半概率是左手系**（det = −1）。

这对"重建张量"毫无影响（$col\cdot col^{\mathsf T}$ 不变号），测试也一直通过。
但**反射不是旋转**，一旦被转成四元数就完全错误。

实测：随机 200 个对称阵，**97 个**得到 det = −1。

修正只需在特征分解末尾判一次行列式、翻转任意一列（不改变张量）。修正后：

```
200 个随机对称阵：det<0 的个数=0，|det−1| 最大=1.332e-15
```

## 4. 广义 SAT：换轴源，不换算法

盒-盒用的轴集合是「3 个面法向 + 3 个面法向 + 9 条棱叉积」。推广到任意凸多面体，
完整的分离轴集合就是：

$$\text{axes} = N_A \cup N_B \cup \{e_a \times e_b\}$$

盒子只是"6 面 12 棱"的特例。所以**不需要换算法**，只需要把"从 3 个坐标轴读轴"
换成"从面表/棱表读轴"，裁剪的凸多边形算法本来就是通用的。

### 选择 SAT 而不是 GJK/EPA

| 方案 | 精确性 | 可验证性 | 复杂度 |
|---|---|---|---|
| **广义 SAT** | **解析精确** | 可与手算/专用实现逐位比对 | `O(F_a+F_b+E_a·E_b)` |
| GJK + EPA | 迭代，~1e-6 | 只能自证收敛 | `O(迭代次数)` |

本项目的每一项都有解析对照，这条更重要。

### 代价上限与加载期拒绝

棱-棱轴数是 `E_a · E_b`，这是 SAT 唯一的规模问题：

| 凸包规模 | 棱数 | 棱-棱候选轴 |
|---|---:|---:|
| 立方体 | 12 | 144 |
| 20 面 | 30 | 900 |
| 64 面 | ~96 | 9 216 |
| 512 面 | 768 | 589 824 ← 不可用 |

所以 `ConvexHullGeometry(max_faces=64)` **在加载阶段就拒绝**过复杂的凸包。
理由：一次 59 万条轴的查询会让仿真失去响应，现象上像死循环，极难定位。
测试第 4 项验证：1200 点的球面点云（2395 个面）默认被拒绝，显式放宽后可以构造。

### 一个符号 bug：侧平面方向

面接触裁剪时，需要把入射面裁到参考面的轮廓内。对于从外部看逆时针的多边形，
内部位于每条有向边的左侧，平面内指向内部的向量是 `cross(normal, edge)`。

我直接把这个**朝内**法向传给了 `_clip_polygon`，而它的约定是保留
`dot(n,p) <= offset`——于是保留的正好是面**外部**，整个面被裁空。

**症状：所有面接触返回 0 点，但棱-棱却正常。** 这个不对称正是定位线索。
修正办法是传朝外法向 `(-inward, -offset)`。

## 5. 球-凸包：最近点，而不是 SAT

球是光滑体，没有面也没有棱，SAT 的轴集合对它不成立（它有无穷多个支撑方向）。
但球的接触完全由**球心到表面的最近距离**决定，所以直接用最近点，精确且更便宜。

两种情形必须分开：

- **球心在外**：最近点必在多面体表面（面内或棱/顶点上）
- **球心在内**：最近点是"最浅的那个面"上的投影，距离记为负

### 一个导致"穿透等于整个半径"的 bug

判断"投影是否落在多边形内"这一步**不能省**：

```python
signed = dot(normal, point - anchor)
projected = point - normal * signed      # 平面投影，法向距离恒为 0
```

如果把 `projected` 直接当候选、再取"所有面里距离最小的"，那么任何
**与某个面共面、但落在该多边形之外**的点都会得到距离 0。

实测症状：球放在凸包顶点外侧 0.2 m（正好与顶面共面），报**穿透 0.2 = 整个半径**。
修正后沿四个方向 × 两档穿透共 8 组全部精确到 1e-9。

## 6. 凸包的接触时刻预测（TOI）

这一节是本轮补上的**最实在的正确性缺口**。在此之前 `toi.py` 只对球有效：
球-球是一元二次方程、球-地面是一元一次，凸包没有解析式，于是**直接跳过子步
切分**。后果不是漏碰撞，而是深穿透——一个子步的位移整个陷进去：

| 场景 | 不切分 | 球（已有切分） |
|---|---:|---:|
| 棱柱落地 | 10.533 mm | 0.148 mm |
| 球落地（基准） | 6.866 mm | **0.000 mm** |

球与凸包差了一个数量级，而 W3 的卖点恰是任意凸多面体。

### 三条路径，一个共同要求：不偏晚

| 组合 | 方法 | 精度 |
|---|---|---|
| 球-球 | 一元二次方程 | **精确** |
| 球-地面 | 一元一次 | **精确** |
| 盒/凸包-地面 | 逐顶点求撞击时刻取最小 | **精确** |
| 球-盒/凸包 | 最近点 + 沿法向 | 保守 |
| 盒/凸包-盒/凸包 | SAT 候选轴逐轴收缩 | 保守 |

**凸包-地面为什么能精确**：地面是平面，凸多面体撞地的点**一定在顶点上**
（极值必在顶点）。而顶点在恒定 `v`、`ω` 下的轨迹是一条**直线**：

$$z_i(t) = z_i + \big(v_z + (\omega \times r_i)_z\big)\,t$$

所以每个顶点给一个精确撞击时刻 $t_i = (z_i - g) / (-\dot z_i)$，TOI 是它们的最小值。
球-地面的一元一次方程只是它的特例：球"无穷多顶点"里最低的那个。

### 凸包-凸包：用 $|\omega|R$ 把旋转变成上界

没有任何解析式能给出"两个**旋转中**的凸包何时接触"——棱扫过的是曲纹面。
但有一条严格不等式：**凸包上任意一点因自转获得的速度不超过 $|\omega|R$**。

于是对任意单位轴 $n$，间隙 $g_n(t) = \max(a_{low} - b_{high},\ b_{low} - a_{high})$
的收缩速率有上界

$$\dot g_n \geq -\Big[\max\big(0,\ \text{side}\cdot(v_B - v_A)\cdot n\big) + |\omega_A|R_A + |\omega_B|R_B\Big]$$

第一项是平移沿该轴的投影（`side` 说明间隙是哪一侧给出的，符号错了就会把
"分离"算成"接近"），后两项是自转。于是

$$t_n = \frac{g_n + \varepsilon}{|\text{收缩速率}|},\qquad \text{TOI} \leq \min_n t_n$$

取**最小**是保守的方向：真实接触不早于任何单轴收完的时刻。对纯平移，沿正确轴的
估计是**精确**的——面-面由面法向、棱-棱由叉积轴给出，与三维解析解逐位一致
（测试第 3 项，10 组随机位姿）。

**偏早和偏晚的代价不对等**：偏早只是多切一刀（推进、检测、发现没接触、继续），
偏晚则漏掉切分、深穿透，甚至让牛顿摆飞出两个球。所以宁可偏早。

候选轴由 `candidate_axes` 统一提供，SAT 与 TOI **共用同一份**。两套各写一遍的话，
轴集合一旦不一致，就会出现"SAT 说没碰到、TOI 说已经到了"这种最难查的分歧。

### 精确切在"间隙 = 0"反而更差：200 µm 余量

第一版把切分点算到间隙恰好为 0，结果盒砸静止盒的穿透从 5.4 mm **升到 8.6 mm**。
原因在窄相：

> 两个盒子恰好相切时，面裁剪多边形的面积退化为零，**只能给出 1 个接触点**。
> 单点约束解不掉整体的法向速度——实测一次求解只把 −7.22 m/s 降到 −4.95 m/s，
> 剩下的速度在本子步继续推进 3.4 mm。

留 200 µm 穿透（远小于 slop 2 mm）就能撑开裁剪多边形，拿到完整的 4 点面流形，
一次把法向速度压到零：

| 场景 | 不切分 | 0 余量 | **200 µm 余量** | 耗时 开/关 |
|---|---:|---:|---:|---:|
| 盒子落地 | 3.483 mm | 1.328 mm | **0.470 mm** | 231 / 41 ms |
| 盒砸静止盒 | 5.439 mm | 8.532 mm | **0.856 mm** | 1199 / 891 ms |
| 棱柱落地 | 10.533 mm | 1.028 mm | **0.148 mm** | 194 / 54 ms |
| 球砸棱柱 | 4.918 mm | 0.000 mm | **0.000 mm** | 243 / 133 ms |
| 球落地 | 6.866 mm | 0.000 mm | **0.000 mm** | 25 / 19 ms |

（1/240 s × 3 子步，240 步；数值为整段仿真中的**峰值**穿透）

"0 余量"那一列是这次实验里最反直觉的一格：**盒砸盒 8.532 mm，比不切分还差**。
这不是回归，而是说明"把 TOI 算得越准越好"是个错误直觉——准的是**解析时刻**，
而下游窄相是离散的，两者在恰好相切处语义不一致。

这不是精度让步，而是**接口适配**：TOI 是解析量、窄相是离散量，两者在"恰好
相切"这个点上语义不同。余量是让离散侧能看见它。

余量只作用于多面体。球没有裁剪退化问题，`sphere_sphere_toi` / `sphere_ground_toi`
保持逐位精确（测试第 6 项专门钉这一点，防止有人把余量顺手加到全部分支）。

### 代价：轴枚举，以及去重带来的顺带收益

凸包-凸包的 TOI 是每对物体 $O(K^2)$ 的轴枚举（$K$ 为棱数），比球的一元二次
方程贵得多。实测代价取决于场景：

- 多体场景（盒砸盒）：891 → 1199 ms，**+35%**
- 单体场景（盒落地）：41 → 231 ms，**+463%**——但绝对值只有 0.8 ms/步，
  属于"固定开销主导"，场景越简单占比越难看

不过这一轮顺手修掉了一个真实浪费：**候选轴里有大量重复**。正六棱柱有 18 条棱，
$18 \times 18 = 324$ 个叉积，实测只产出 **8 条互不相同的轴**（256 → 8，含面法向）。
原因是棱方向本身就重复：六棱柱的 18 条棱只有 4 个方向。

`candidate_axes` 因此先**按方向去重**再叉乘，并按 `n` 与 `-n` 同键合并
（`_separation` 对取反不变，它们本就是同一条判据）。去重只剔除**完全相同的方向**，
所以 SAT 的 max 与 TOI 的 min 都不变——`test_hull` 第 9 项"广义 SAT 在盒子上
退化一致"仍以 3.3e-16 通过。

收益是双向的：8 体场景整体从 3659 ms 降到 2212 ms（**1.65×**），TOI 自身也从中受益。

### 已经触地就返回 `None`

只要有顶点已经贴地，物体就处在**持续接触**里，由求解器接管，不该再报未来事件。

这条的写法有讲究：不能"跳过贴地的顶点、继续算别的顶点"。后者会给出"另一侧
顶点何时落地"的时刻——听起来合理，实则有害。实测一个底面恰好贴地的盒子报出
$t = 0.3001$ s，而它其实一直躺着；子步于是在毫无接触的时刻被切开一次，白白
扰动求解流程。

### 一个诚实的边界：稠密堆叠

单次撞击的效果很干净（上表 3–70 倍）。但**8 层棱柱整体自由落体**不属于这一类：
实测峰值穿透在 10–30 mm 之间跳动，开关 TOI 都可能变好或变差。

原因不是 TOI 失效，而是那种场景已经超出离散求解器能表达的范围——8 个物体链式
同时接触、没有 warm starting，峰值穿透主要由"一帧内速度被改了 8 次"决定。
在这种量级下比较两个都失败的数字没有意义，所以这一节不拿它当卖点。

要改善它，正确方向是**接触缓存 + warm starting**（沿用上一帧的冲量），而不是
继续加密 TOI。

**又一组解析对照**：正四面体与正八面体的三个主惯量完全相等（各向同性），

$$I_{\text{四面体}} = \frac{mL^2}{20} = \frac{3.2 \times 1.24^2}{20} = 0.2460 \;\checkmark$$
$$I_{\text{八面体}} = \frac{mL^2}{10} = \frac{3.6 \times 0.594^2}{10} = 0.1270 \;\checkmark$$

结果：终态最大速度 0.0007 m/s、最大穿透 1.59 mm，四个物体的最低点分别是
−1.6 / −0.4 / −0.6 / −0.0 mm（都在 slop 之内）。

球只有 4 个物体中的 6 个物体对，候选对峰值 3 —— 凸包的 AABB 用变换后的顶点精确计算，
比包围球紧得多。

## 9. 边界：凹体必须拆成凸块

凸包是凹体的**外近似**，凹进去的部分会被填满。L 形棱柱的实测：

| | 体积 |
|---|---:|
| 真实 L 形 | 3.0000 |
| 凸包 | 3.9000 |
| 比值 | **1.300** |

这不是缺陷，而是数学事实：所有窄相算法都要求凸性，凹体没有良定义的
"最小穿透轴"。业界做法一律是**凸分解**（V-HACD / CoACD）+ 组合体。

所以正确的路线是：

$$\text{凹 mesh} \xrightarrow{\text{凸分解}} \text{若干凸块} \longrightarrow \text{组合体（单刚体、多形状）}$$

组合体的抽象已经清楚：**一个刚体、一组速度、一个惯量张量**，内部部件之间没有相对运动；
碰撞是部件两两检测、结果合并成一个流形集合；宽阶段用部件 AABB 的并集。

这条路线图的后半段**已经落地**（`CompoundGeometry`），缺的只是前半段：目前凹体要么
在 JSON 里**手工**拼出部件（可行、已有测试覆盖），要么用凸包外近似。
