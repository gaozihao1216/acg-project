## 3. 八组实验

### 3.1 实验总览

| # | 名称 | 验证目标 | 耗时 |
|---|---|---|---:|
| 01 | `baseline` | 基础链路是否正常 | 6.0 s |
| 02 | `camera_low` | 相机参数是否可控 | 3.9 s |
| 03 | `camera_closeup` | 视场角 / 长焦效果 | 5.8 s |
| 04 | `light_soft` | 面光尺寸对阴影软硬的影响 | 6.3 s |
| 05 | `light_hard` | 同上（反方向） | 5.7 s |
| 06 | `material_roughness` | 粗糙度对金属高光的影响 | 5.3 s |
| 07 | `layout_stack` | 复杂布局 + W2 构图预演 | 5.0 s |
| 08 | `hero` | 高分辨率高质量出图能力 | 39.4 s |

除 `06/07` 替换了物体列表外，其余实验都只是对基础场景做**少量字段覆盖**。

### 3.2 逐组说明

**01_baseline —— 基线**
五种基础几何（box×2、sphere、cylinder、capsule）+ 三点布光（主光 / 补光 / 轮廓光）。
确认：几何生成、材质、阴影、相机朝向、色彩管理全部正常。

**02_camera_low —— 低机位**
`camera.position` 从 `[4.1,-4.5,2.35]` 降到 `[4.7,-3.9,0.78]`，`fov` 42→46。
效果：物体显得更高大，背景被压缩成深色块，空间感更强。
**结论**：相机参数完全由 JSON 驱动，无需改代码。

**03_camera_closeup —— 长焦特写**
`fov` 42→38，相机拉近到 3.7 / -3.6 / 1.85 并重新对准主体。
效果：主体占画面 2/3，透视压缩明显。
**踩坑记录**：第一次把机位放到 3.5 m 处配 `fov=30`，可见宽度只有 1.9 m，
主体直接被裁掉。**视场角收窄时必须同步拉远相机**，否则构图失败。

**04_light_soft / 05_light_hard —— 光照软硬对比**
只改主光 `size`（2.6 → 8.0 / 0.35）与环境光强度（0.3 → 0.70 / 0.05）。
效果对比：

| | 04 柔光 | 05 硬光 |
|---|---|---|
| 阴影边缘 | 几乎完全弥散 | 锐利清晰 |
| 画面反差 | 低，偏平 | 高，形体明确 |
| 金属球反射 | 大面积柔和高光 | 小而亮的锐利高光 |

**结论**：**面光尺寸是控制画面调性最有效的单一参数**，比调能量更明显。

**06_material_roughness —— 材质对比**
换成 4 个完全相同的金属球，只有粗糙度不同：`0.03 / 0.22 / 0.52 / 0.88`。
效果：从镜面反射（能看清地面与相邻球的倒影）连续过渡到几乎无高光的磨砂。
**结论**：这是后续做"材质/渲染质量"论证时最有力的单张图。

**07_layout_stack —— 堆叠布局**
三块逐渐变小的盒子垂直叠放 + 金属球 / 磨砂球 / 圆柱散落。
**这一组不是为了好看，是为了 W2 预演**：等下有了物理，这段布局直接变成
"落体堆叠是否稳定"的初始状态，构图和相机参数可以复用。

**08_hero —— 主视觉**
1600×900 / 192 采样 / 曝光 +0.15。用于中期报告与口头报告。
39 秒的耗时说明**高采样确实贵**，日常调参必须用低采样。

## 4. 关键技术结论

### 4.1 曝光：区域光能量比想象中低得多

第一次渲染用了主光 900 W，结果地面被打成纯白、红色变粉、蓝色变浅。
按 `辐照度 ≈ P / (4πd²)` 估算，5 米处三盏灯合计约 4.8 W/m²，
远超 1.0 的过曝阈值。

**经验值（5 米距离，浅灰地面）**

| 灯位 | 能量 | 尺寸 |
|---|---|---|
| 主光 | 250–450 W | 2–3 m |
| 补光 | 主光 × 1/4 | 4 m |
| 轮廓光 | 主光 × 1/2 | 3 m |
| 环境光强度 | 0.25–0.4 | — |

### 4.2 Filmic 会压饱和度，颜色要往上补

Blender 默认的 Filmic 视图变换对高光有很长的滚降，代价是**中低调的饱和度被压低**。
直接把 sRGB 的 `(200, 80, 80)` 换算成 `(0.78, 0.31, 0.31)` 写进去，
渲染出来是灰粉色。

**做法**：把基础色的饱和度显著提高，例如红色写成 `[0.72, 0.055, 0.03]`。
这个值看着"过饱和"，渲染后才是正常的红。

### 4.3 降噪比堆采样划算

64 采样 + OIDN 降噪在简单场景下已经看不出噪声，单帧 5 秒。
若改到 256 采样，时间 ×4 而噪声只减半。
**日常迭代一律 48–64 采样 + 降噪；只有最终出片才上 192。**

### 4.4 迭代速度满足需求

5–6 秒/帧意味着"改参数 → 看结果"的循环不到 10 秒，
足以支撑大量参数扫描。**但这也意味着动画序列要控制帧数**：
120 帧 × 6 秒 ≈ 12 分钟/条，W2 起需要规划。

## 5. 已知限制（留给后续阶段）

| 限制 | 影响 | 计划 |
|---|---|---|
| 无景深（DOF） | 特写时背景不够"虚" | 出片阶段给 `CameraSpec` 加 `focus_distance` / `aperture` |
| 无运动模糊 | 动态场景少了速度感 | W2 加 `motion_blur` 渲染开关 |
| 只有透视相机 | 无正交视图 | 若需要俯视图再加 `ortho` 类型 |
| 仅静态单帧 | 无法出视频 | **W2 实现 `render_anim.py`**：读位姿序列逐帧渲染 |
| 地面不参与物理 | 只是视觉平面 | W2 另建静态碰撞平面，外观复用 |
| Cycles 只用 CPU | 无法用 GPU 加速渲染 | 优先级低（5 秒已够快） |

## 6. 对 W2 的接口准备

Phase 0 已经把 W2 需要的东西铺好了：

| W2 需要 | Phase 0 已就绪 |
|---|---|
| 参数化几何 → 碰撞体 | `GeometrySpec` 四种子类，含 `bounding_radius()` |
| 刚体质量 | 场景 JSON 的 `mass` 字段（缺省按体积×1000 估算） |
| 转动惯量 | `compute_inertia()` 已实现四种图元 |
| 姿态表示与积分 | `quat_integrate()` 已实现 |
| 局部↔世界坐标 | `TransformSpec.transform_point()` / `transform_direction()` |
| 场景参数化 | JSON `solver` 段（W2 追加） |
| 渲染素材 | `07_layout_stack` 的构图与相机参数可复用 |

**W2 唯一要新写的是**：半隐式欧拉积分器、球-球/球-平面窄相碰撞、顺序冲量求解器，
以及 `render_anim.py`（位姿序列 → 逐帧渲染 → ffmpeg）。
