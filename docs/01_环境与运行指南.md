## 1. 目录结构

```
project/
├── Code/                       所有代码（详见 Code/README.md）
│   ├── src/                    纯 Python 库（不依赖 bpy）
│   │   ├── mathutils/          四元数、三维向量
│   │   ├── geom/               几何、变换、惯量、凸包、网格 IO、资产
│   │   ├── scene/              场景 JSON 解析与参数覆盖
│   │   └── physics/            刚体物理（宽阶段/窄相/求解器/TOI/世界）
│   ├── render/                 Blender 渲染层（依赖 bpy）
│   │   ├── blender_builder.py  SceneSpec → bpy 场景
│   │   ├── render_static.py    静态单帧渲染
│   │   ├── render_anim.py      位姿序列 → 关键帧 → 视频
│   │   └── render_asset.py     资产 → .blend + QA 预览图
│   ├── scenes/                 场景 JSON（demo_* / sim_* / generated/）
│   ├── scripts/                run_sim / analyze_object / assemble_scene /
│   │                           reproduce / bench_* / make_*_scene
│   ├── assets/                 测试用 OBJ / STL / 点云
│   └── tests/                  15 个模块，140 项检查，一键 run_all.py
│
├── results/                    产出
│   ├── phase0/                 W1 的 8 张渲染对比图
│   ├── w2/                     球/盒演示视频、位姿序列、基准文本
│   ├── w3/                     物体资产案例目录 + 凸体场景（可逐字节复现）
│   └── w4/                     暖启动 A/B 对照基准
│
├── docs/                       13 篇技术文档（按写作时间编号，后篇可能推翻前篇）
│
├── 项目实现规划.md             整体 12 周路线图
├── ACG_Project_Announcement.pdf        原版公告
└── ACG_Project_Announcement_中文版.pdf 中文译本
```

**读文档的顺序**：编号只表示写作先后，不表示依赖。能力边界以
`Code/README.md` 的"当前能力与限制"与源码为准；被后篇推翻的结论会在
前篇里以 `> **补充（…）**` 的形式留注记（例如 `docs/05` §7、`docs/06` §6–§7）。

**为什么 `src/` 不依赖 bpy**
求解器（W2 起）需要在普通 Python 里跑，不能拖着一个 Blender 环境。
因此几何、变换、惯量、场景解析全部写成纯 Python，只有 `render/` 才 `import bpy`。

## 3. 三种运行方式

### 3.1 渲染单个场景（最常用）

在 `project/` 目录下执行：

```powershell
& "C:\Program Files\Blender Foundation\Blender 3.6\blender.exe" `
  --background --factory-startup `
  --python "Code\render\render_static.py" -- `
  --scene "Code\scenes\demo_basic.json" `
  --out   "results\phase0\my_test.png"
```

**关键点**

- `--background`：无界面运行，不弹 Blender 窗口
- `--factory-startup`：忽略用户自定义配置与插件，保证可复现
- `--` 之后才是本脚本的参数，之前都是 Blender 自己的参数
- 必须用 **Blender 自带的 Python**，不能用系统 python（系统 python 里没有 `bpy`）

### 3.2 批量渲染（推荐，省启动开销）

一次启动 Blender 渲染多张，清单格式见 `Code/scenes/generated/manifest.json`：

```powershell
& "C:\Program Files\Blender Foundation\Blender 3.6\blender.exe" `
  --background --factory-startup `
  --python "Code\render\render_static.py" -- `
  --manifest "Code\scenes\generated\manifest.json"
```

每张图渲染前都会重置 Blender 场景，因此材质名、物体名不会互相污染。

### 3.3 跑参数对比实验（用系统 Python）

```powershell
python Code\scripts\run_phase0_experiments.py
```

常用参数：

| 参数 | 作用 |
|---|---|
| `--list` | 只列出实验清单，不渲染 |
| `--only 06_material_roughness` | 只跑指定的一项（写代码调参时最常用） |
| `--out-dir DIR` | 改输出目录 |
| `--blender PATH` | 指定 blender.exe |

脚本会先把每项实验的场景写到 `Code/scenes/generated/<name>.json`，
**并立即用正式解析器校验一遍**——参数写错了会在这里报错，而不是等 Blender 跑到一半才失败。

## 4. 加一项新实验

只需在 `Code/scripts/run_phase0_experiments.py` 的 `EXPERIMENTS` 列表里追加一项：

```python
{
    "name": "09_my_test",
    "desc": "说明这一组想验证什么",
    "patches": {
        "camera.position": [6.0, -6.0, 3.0],
        "lights.0.energy": 500.0,
    },
},
```

`patches` 的键是**点号路径**，数字表示列表下标：

| 路径 | 含义 |
|---|---|
| `camera.position` | 相机位置 |
| `lights.0.energy` | 第 1 盏灯的功率 |
| `objects.2.material.roughness` | 第 3 个物体的粗糙度 |
| `objects` | 整体替换物体列表（换布局时用） |
| `render.samples` | 采样数 |

写错的路径会在生成阶段直接 `KeyError`，并指出是哪一段不存在。

## 5. 常见问题

| 现象 | 原因与处理 |
|---|---|
| `ModuleNotFoundError: No module named 'bpy'` | 用系统 python 跑了 `render_static.py`。必须用 blender.exe |
| `ImportError: cannot import name ...` | `Code/` 没在 `sys.path` 里。入口脚本会自动处理，若自己写脚本需 `sys.path.insert(0, CODE_ROOT)` |
| 渲染出来一片黑 | 灯光能量过低，或相机朝向反了。先用 `01_baseline` 确认基础链路 |
| 画面发白、颜色发灰 | 曝光过高。区域光的 `energy` 单位是瓦特，5 米距离上 300–500 W 已足够 |
| 出图很慢 | 降 `render.samples`（64 → 32）或降分辨率；`08_hero` 用了 192 采样所以慢 |
| 中文输出乱码 | PowerShell 控制台编码问题，只影响终端显示，PNG 与 JSON 都是 UTF-8 |

## 6. 渲染耗时参考

本机（Cycles CPU）实测：

| 场景 | 分辨率 | 采样 | 耗时 |
|---|---|---|---|
| 01–07 常规实验 | 960×540 | 64 | **4–6 秒** |
| 08_hero | 1600×900 | 192 | **39 秒** |

8 张一次跑完约 **79 秒**。这个速度足以支撑"改参数 → 看效果"的快速迭代，
W2 起做动画序列（比如 120 帧）时按 6 秒/帧估算约 12 分钟/条，需要注意控制帧数。
