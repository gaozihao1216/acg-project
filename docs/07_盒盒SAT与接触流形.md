# 盒-盒 SAT 与接触流形裁剪

> 窄相：`Code/src/physics/sat.py`
> 测试：`python Code/tests/test_box_box.py`（10 项）
> 演示：`results/w2/demo_box_stack.mp4`（37 帧 / 24 fps / 1.5 s）

## 1. 为什么盒-盒是这一步的分水岭

球-球、球-盒都只有 **1 个**接触点。盒-盒不同：

| 接触形态 | 点数 | 说明 |
|---|---:|---|
| 面贴面 | 4 | 整块面积接触，必须离散成支撑多边形 |
| 棱碰棱 | 1 | 点位置由两条棱共同决定 |
| 顶点碰面 | 1 | 退化为球-盒的形式 |

**单点流形约束不住旋转。** 盒子会绕那个点慢慢倾倒，仿真不会报错，
只是几分钟后整个塔歪掉——这类问题最难查。

## 2. 三段式算法

### 2.1 SAT：15 条候选轴

```
A 的 3 个面法向  +  B 的 3 个面法向  +  9 条棱叉积  = 15
```

对每条轴计算分离量：

$$\text{sep}(n) = |\mathbf{d}\cdot n| - \big(r_A(n) + r_B(n)\big),\qquad r(n)=\sum_i |\text{axis}_i\cdot n|\,h_i$$

`r(n)` 是盒子在该轴上的**投影半径**。因为盒子关于自身中心对称，用 `|d·n|`
即可（不必区分正反朝向）；分离量为正即两盒分离，可立即返回。

取分离量**最大**（最接近 0）的那条轴作为接触法向，穿透深度 `= -sep`。

### 2.2 面对面：参考面 / 入射面裁剪

若最优轴是某个面的法向：

1. **参考面** = 拥有该法向的盒子上的那个面
2. **入射面** = 另一个盒子上**法向最接近反向**的那个面
3. 把入射面的四边形用参考面的 4 个侧平面**裁剪**
4. 保留落在参考面内侧（穿透）的顶点，穿透量 = 到参考面的有符号距离

### 2.3 棱对棱：单点

沿叉积轴取两个盒子各自"最靠前"的棱，求两条线段的最近点，取中点。

### 2.4 法向约定

全程保持 **从 A 指向 B**。参考面在 B 上时，内部用"从 B 指向 A"的朝向计算，
返回前统一翻回。交换 A/B 顺序时法向严格取反——测试里专门验证了这一点
（点积 = −1.000000000），因为一旦搞反，症状是"碰撞时物体互相吸引"。

## 3. 两个只有靠测试才能发现的 bug

这两个 bug **都不会抛异常**，只是给出错误的数字。仿真照样跑，只是盒子会慢慢倾斜。

### 3.1 面顶点按 Z 字序排列

生成盒子某个面的 4 个顶点时，`for su: for sv:` 的自然结果：

```
(-,-) → (-,+) → (+,-) → (+,+)
```

这不是环绕顺序，两条对角边会**交叉**——多边形是个自交的蝴蝶形。裁剪算法假设
凸多边形的顶点是首尾相接的，于是结果全错。

正确顺序是绕行一圈：

```
(-,-) → (+,-) → (+,+) → (-,+)
```

**症状**：平放堆叠本该得到 4 个接触点，实际只得到 2 个。

### 3.2 入射面只看了正方向

选入射面时我写的是"对每个轴计算 `-dot(axis, ref_normal)` 取最大"——
**只考虑了轴的 + 方向**。

对 +z 的参考法向，真正最反向的面是 **−z 面**（点积 −1），但三个**轴**与 +z 的点积是
`0, 0, 1`，取负后最大的是 0，于是选中了 x 轴。入射面整个选错，裁剪出来的是侧面。

正确做法是先比较 `|dot|` 找出最对齐的轴，再按符号取反向的那一侧：

```python
best_axis = argmax |dot(inc_axes[i], ref_normal)|
inc_sign  = -1.0 if dot(inc_axes[best_axis], ref_normal) >= 0 else 1.0
```

### 3.3 还有一个"测试自己错了"的坑

体对角线竖直的立方体，最低顶点到中心正好是 `√3/2 = 0.8660254`。
我图省事写了 `z = 1.316`（手写四位小数），结果穿透算出来是
`0.0500254` 而不是 `0.05`，`1e-6` 的断言失败，看起来像窄相算错了。

**参考值必须写成表达式**（`0.45 + math.sqrt(3)/2`），不能手抄小数。

## 4. 接触特征 ID

`ContactPoint` 新增 `feature_id`，用于跨帧匹配接触点。

```
face 接触： (ref_face_id × 100) + vertex_id
             ref_face_id = 0..2（参考面在 A 上）
                        3..5（参考面在 B 上）
             vertex_id   = 0..3（入射面原顶点）
                           5..（裁剪产生的新顶点，按裁剪顺序递增）
棱-棱：      (20 + i*3 + j) × 100
```

裁剪时顶点标签会**沿多边形传递**：原顶点保留自己的编号，被切出来的新顶点拿一个新号。
这样"哪些点是同一个点"在相邻帧之间可比对。

**为什么不能用数组下标**：裁剪产生的顶点数会随姿态变化，
一旦某帧从 4 点变成 3 点，下标就全错位了，暖启动会把冲量喂给错误的接触点。

测试验证：静置 0.8 秒、8 次采样，ID 集合恒为 `{201, 205, 207, 208}`。

（第一版测试这里**假通过**了一次：上盒初始位置写得太深，被 Baumgarte 推开后彻底分离，
8 次采样全是空集，"全部相同"平凡成立。现已加断言要求集合**非空**。）

### 4.1 契约推广到所有路径（W5 修订）

上面这条原则当初只落在了 SAT 裁剪上，另外两条路径各自违反了一次：

| 路径 | 旧做法 | 症状 |
|---|---|---|
| 地面接触（盒 / 柱 / 胶囊 / 通用解） | 同一物体的多点**共用** `feature_id=0` | 偏心负载下四角累积冲量实测 0.011 / 0.015 / 0.030 / 0.026（相差近 3 倍），缓存只存得下一条；下一帧把这个值施给四角，净冲量偏大、分布被抹平 |
| GJK 流形（柱 / 胶囊 / 锥 / 台 / 椭球 / 球冠） | `feature_id = index`，即列表下标 | 正是上面 118 行讲的同一个错，只是换了个模块 |

现在两条都改成"由几何特征决定"：

```
地面-盒：        4*ix + 2*iy + iz（顶点序号）→ 底面四角就是 {0, 2, 4, 6}
地面-柱/锥/台/冠： 端面序号 × 4 + 圆周序号 → {0, 1, 2, 3}
地面-胶囊：       母线端点序号 → {0, 1}
GJK 流形：       tag_a × 512 + tag_b（两侧支撑特征标签的组合）
```

标签的唯一来源是 `support.feature_world_tagged()`，`feature_world()` 退成它的薄包装：
裁掉一个浅点不会让其余点的标签整体前移。

验收见 `tests/test_contact_identity.py`（7 项）。最能说明问题的是第 3 项：盒子倾斜
8.6° 后只剩两个角接触，剩余 ID 是 `{4, 6}` 而不是被重新编号的 `{0, 1}`——
原子集 `{0, 2, 4, 6}` 的真子集。

**一处必须如实记录的代价**：per-point 身份让暖启动恢复的是真实分配，而不是过去那个
"存一个标量再均摊回四角"的效果。3 层塔、只迭代 **1** 次时，暖启动的相对收益从 1.97 倍
掉到 0.92 倍——因为 4 点支撑一个刚体是静不定问题，1 次迭代连分配都没解出来，旧行为的
"收益"其实是每帧强行抹平到了对称解上。迭代 ≥ 2 时新实现全面更好（2 次：0.314 mm vs
旧的 1.961 mm）。`tests/test_warm_start.py` 因此把该用例的配置定在 2 次迭代，并把
四档实测数据写进了它的 docstring。

第 9 项的判据**刻意独立于 SAT 的实现**，避免"拿一个可能同样错的参考实现去对比"：

- **内切球相交 ⇒ 必然重叠**：盒内最大内切球半径是 `min(half)`，两球相交则两盒必相交
- **包围球分离 ⇒ 必然不重叠**：球半径是 `|half|`

落在两者之间的构型是"说不准"，跳过不计——保证判据是**充分**的而非"看起来对"。

## 6. 堆叠稳定性实测

这是盒-盒真正的考验。固定 `substeps=3, iterations=8, dt=1/240`，盒子 0.8 m 见方：

| 层数 | 各层 z（实测） | 期望 | 水平漂移 | 直立度 | 最大残余速度 |
|---:|---|---|---:|---:|---:|
| 3 | 0.398 / 1.196 / 1.994 | 0.4 / 1.2 / 2.0 | 2.8 mm | 1.00000 | 0.004 |
| 4 | 0.398 / 1.196 / 1.994 / 2.793 | … / 2.8 | 9.6 mm | 1.00000 | 0.002 |
| 5 | 0.398 / … / 3.591 | … / 3.6 | 8.4 mm | 1.00000 | 0.023 |

**5 层塔在 8 次迭代下完全稳定**，下陷只有 2 mm（= `slop`），直立度 1.00000。

这比第 05 号文档预期的好。原因：盒子接触的 4 个点**法向完全相同**，
Gauss–Seidel 在同一个方向上反复修正，收敛比"法向各异的一维链"快得多。
此前测出的"接触数 ↑ → 迭代需求平方增长"是在球链上，几何不同，不能直接外推。

（顺带一个反直觉的观察：5 层塔用 18 kg 的球以 6 m/s 撞底层，塔**不会倒**——
塔总质量 200 kg 以上，冲量太小。这本身是稳定性良好的体现。）
