# 盒-球碰撞与转动动力学

> 测试：`python Code/tests/test_box_collision.py`（12 项）
> 演示：`results/w2/demo_boxes.mp4`（37 帧 / 24 fps / 1.5 s）

## 1. 这一步的真正价值

球-球碰撞里，接触点的力臂 **恒与法向平行**：

$$\mathbf{r} = \mathbf{n}\left(r - \frac{\delta}{2}\right) \quad\Longrightarrow\quad \mathbf{r} \times \mathbf{n} = 0$$

所以**法向冲量从不产生力矩**，球的旋转只能由摩擦带来。这意味着此前所有测试
都没有真正考验过「力臂 → 力矩 → 世界坐标逆惯量 → 四元数姿态积分」这条链路。

盒-球不同：球撞在盒子边缘时 `r × n ≠ 0`，盒子必须转起来。
**这一步是转动动力学第一次进入回路。**

这一点在 W2 设计时就留好了，所以加盒子**没有改动求解器一行代码**。

## 3. 新增的窄相

### 3.1 球-盒（`collide_sphere_box`）

盒子是凸体，把球心转到盒子局部坐标后**夹紧**到盒子范围内，得到的必然是该凸体上
离球心最近的点，因此这是**精确解而非近似**：

```
local    = Rᵀ (c_sphere − c_box)
closest  = clamp(local, −half, +half)
delta    = local − closest
```

两种情形：

| 情形 | 判据 | 法向 | 穿透 |
|---|---|---|---|
| 球心在盒外 | `\|delta\| > 0` | `delta / \|delta\|` | `r − \|delta\|` |
| 球心在盒内 | `delta ≈ 0` | 最近的盒面方向 | `r + 到该面的距离` |

第二种是深度穿透的退化情形——最近点退化成球心自身，方向没有定义，
必须退回到「离哪个面最近就从哪个面出去」。

### 3.2 盒-地面（`collide_box_ground`）

把 8 个顶点变换到世界坐标，凡低于地面的就产生一个接触点，按穿透深度取最深的 4 个。

**为什么必须是多点**：单个接触点只约束 1 个方向的平动，盒子绕该点的旋转完全自由，
表现为持续抖动与缓慢倾斜。4 个点分布在一个面上，法向约束天然阻止翻转。
这是盒-地面与球-地面最本质的差别。

## 5. 两个犯过的错

### 5.1 测试选错了形状（看起来像代码错了）

第一版「惯量按形状计算」用的是 `(0.9, 0.9, 0.3)` 和 `(0.3, 0.3, 0.9)` 两个盒子，
期望它们的 `Iyy` 不同。实测**完全相等**（都是 7.5），看起来像惯量算错了。

复核解析式：

$$I_{yy} = \frac{m}{12}(s_x^2 + s_z^2)$$

两个盒子恰好**互为转置**（把 x 和 z 互换），而 `Iyy` 只看 `sx² + sz²`，
因此必然相同。**是测试设计有缺陷，不是代码有错。**

改用直接对逆惯量算符施加单位力矩的方式检验，既精确又不受形状巧合影响。

### 5.2 力矩方向搞反了

第一版断言「撞击点在盒子上方 → 盒子应绕 −y 转」。实测为 +y，我以为是符号错。

复核：球从 −x 方向撞来，盒子受到的法向冲量沿 **+x**（被打向 +x）。
力臂 `r ≈ (−0.4, 0, +0.3)`，力矩

$$\mathbf{r} \times \mathbf{F} = (-0.4,0,0.3) \times (J,0,0) = (0,\ +0.3J,\ 0)$$

**是 +y。** 物理上：盒子左侧上部被向右推，顶部向右倾倒，正是绕 +y 旋转。

错在把「球受到的反向冲量」当成了盒子受到的冲量。**仿真是对的，测试的期望值错了。**

## 6. 盒-盒的拦截策略

盒-盒（SAT + 流形裁剪）尚未实现。这里的风险不是「不工作」，而是**静默不响应**：
场景里放了两个盒子，它们互相穿过却毫无反应——这类问题极难排查。

因此加了两道闸：

1. **加载阶段**：若两个盒子的**包围球相交**，直接报错并指明是哪一对
2. **运行阶段**：`_collide_pair` 遇到真正靠近的盒-盒时抛 `NotImplementedError`

判据用包围球相交而不是「只要场景里有两个盒子就拒绝」——否则
「同一场景里放两个永远不会相遇的盒子」也无法运行了。包围球不相交 ⇒ 必然不接触，
可以安全放行。

## 7. 与 TOI 分段的冲突

TOI 预测目前只对球有效（球-球是一元二次方程，球-地面是一元一次）。
盒子的最低点是**旋转后的顶点**，接触时刻需要另一套推导，尚未实现。

处理方式：`toi.py` 里对非球几何直接返回 `None`。
这只会让盒子场景**失去子步切分**，碰撞仍会在子步边界的常规检测中被处理，
**不会漏碰撞**。

真正的解法不是给盒子补 TOI，而是按第 05 号文档的结论——上暖启动 + 子步优先。
盒-盒那一步必须同时建立**稳定的接触点 ID**，暖启动才有缓存依据。
