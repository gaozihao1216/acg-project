## 3. 求解器在做什么

### 3.1 单步流程

每个子步（`physics_dt / substeps` = 1/480 s）依次：

```
1. 积分速度      v += g·h，并施加阻尼
2. 碰撞检测      生成接触流形
3. 约束求解      顺序冲量迭代 12 次
4. 积分位置      x += v·h；q ← normalize(q + 0.5h·ω⊗q)
```

**顺序很重要**：接触求解必须发生在位置更新之前（semi-implicit Euler），
而且**碰撞检测必须在加重力之后**——否则"碰撞前接近速度"会漏掉本步重力，
快速下落时恢复系数被低估，球会越弹越低。

### 3.2 法向冲量

对每个接触点，约束是"法向相对速度 ≥ 0"（不允许继续靠近）：

```
vn  = (v_b + ω_b×r_b - v_a - ω_a×r_a) · n
K   = 1/m_a + 1/m_b + n·((I_a⁻¹(r_a×n))×r_a) + n·((I_b⁻¹(r_b×n))×r_b)
dj  = (vn_target - vn) / K
P_new = max(0, P + dj)          # 单侧约束：只能推，不能拉
```

`max(0, ...)` 是单侧约束的核心。漏掉它，物体会互相"粘住"。

### 3.3 四个关键参数

| 参数 | 作用 | 本次取值 |
|---|---|---|
| `restitution` | 法向反弹比例 | 每个球 0.35–0.55 |
| `friction` | 切向冲量上限 `μ·P_n`（库仑锥近似） | 0.22–0.70 |
| `baumgarte` | 位置修正强度 `β/h·(pen - slop)` | 0.25 |
| `slop` | 穿透容差，防止静置抖动 | 0.002 m |
| `restitution_threshold` | 低于此接近速度忽略恢复系数 | 1.0 m/s |

`restitution_threshold` 是静置能否收敛的关键：没有它，静置物体会无限微弹。

### 3.4 恢复系数为什么要"预处理时捕获"

恢复系数必须基于**碰撞前**的接近速度。如果在迭代中用瞬时速度乘恢复系数，
每轮迭代都会注入能量，物体会越弹越高。所以 `_build_constraints` 阶段
就把 `vn0` 固定下来，迭代过程只朝固定的目标速度收敛。

### 4.2 一个反直觉的坑：参考解不能用初始位置

第一版测试把**初始时刻**的两球质心连线当作法向，算出期望值，
结果仿真值偏差 0.43，看起来像求解器出了问题。

手算复核：两球在靠近过程中位置一直在变，**碰撞发生在它们移动到相切位置的那一刻**，
此时法向已经转到了 30.34°，而不是初始位置的 16.7°。用 30.34° 重算，
解析解与仿真值完全吻合。

所以正确的做法是：**先推进到"下一步即将检测到接触"的状态，取那一刻的真实位置
代入闭式公式**，再走一步让求解器施加冲量。两者基于同一组位置，才能逐位比对。

这个坑对后续盒-盒 SAT 同样适用：**法向永远由接触时刻的几何决定，不能缓存初始状态。**

### 4.3 可视对照

`results/w2/demo_offcenter.mp4` — 25 帧 / 24 fps / 1.0 s

同一个高度同时释放两个球：
- **左（蓝）**：正对基球中心落下 → 反弹后**始终在基球正上方**，`vx` 恒为 0
- **右（橙）**：偏移 0.28 m 落下 → 反弹后获得 `vx=+1.94, vz=+0.90`，明显斜向飞出

### 4.4 多体同时接触

顺序冲量是**逐个**处理接触的（Gauss–Seidel 迭代），不是联立求解。所以必须回答：
当三个物体在同一时刻互相挤压时，结果会不会错？

测试构型：三球等质量、中间球被左右两球同时挤压（两个接触在第一步同时存在）。
由对称性，解析解为两端 `∓e·v`、中间**恰好为 0**。

```
[PASS] 对称三体同时挤压（12 次迭代）  最大误差 = 1.48e-10
[PASS] 物体顺序无关性                正序/逆序差异 1.48e-10
[PASS] 动量守恒与能量不增            9.000 J → 4.410 J（比值 0.49 = e²）
[PASS] 四体同时挤压                  终态 vx=[-1.399, 0, 0, +1.399] = ±e·v
```

**迭代到收敛后，顺序冲量给出的是正确的联立解，且与遍历顺序无关。**
误差每轮衰减约 8 倍（≈0.9 位十进制/轮），所以 12 次迭代有充足余量：

```
it1: err=1.275   it2: 0.159   it3: 0.020   it4: 0.002   it6: <0.0005
```

关键在于 `_build_constraints`：**所有接触的"碰撞前接近速度"都在施加任何冲量之前
一次性捕获**。否则先处理的接触会污染后处理接触的反弹目标，结果就会随顺序变化、
能量也会失控。

**但接触数一多，收敛会显著恶化：**

| 球数 | 接触数 | 收敛到 err<0.01 所需迭代 |
|---:|---:|---:|
| 3 | 2 | 6 |
| 5 | 4 | 16 |
| 7 | 6 | 32 |
| 9 | 8 | > 32 |

近似平方增长——Gauss–Seidel 每轮只能把信息传给相邻接触。
**这直接决定了盒-盒堆叠的难度**：一层盒-地面 4 点 + 盒-盒面接触 4 点，
堆 4 层就是 20+ 接触，靠硬迭代会明显塌陷。**在堆叠之前必须加暖启动。**

另外测了"固定总工作量 12，在迭代与小步长之间怎么分配"：

```
sub1/it12: 0.0000    sub3/it4: 0.0025    sub6/it2: 0.1594    sub12/it1: 1.2750
```

**小步长替代不了迭代。** 对一次性高速撞击，碰撞只发生在第一个子步，
后续子步物体已分离、无接触可解，"12 个小步"退化成了"只迭代 1 次"。

### 4.5 模拟"同时"的根源：初始互相嵌入

同一个三球对撞（等质量、e=1、左球 3 m/s），只改变初始重叠量：

| 初始重叠 δ | 终态 (v_A, v_B, v_C) | 对应物理 |
|---:|---|---|
| **0（恰好相切）** | **[0, 0, 3]** | 波传播式 —— 钢球等硬物的真实行为 |
| 1e-6 及以上 | [-1, 2, 2] | 同时式 —— 对应"整体同时变形"的软材料 |

`[0,0,3]` 与 `[-1,2,2]` **都满足动量守恒与能量守恒**。刚性模型无法在两者之间选择，
因为它把材料信息丢掉了。真实世界里哪个出现，取决于弹性波速 `c=√(E/ρ)` 与
接触时长的比值：钢的 `c≈5050 m/s`，穿过 0.3 m 只需 6e-5 s，短于接触时长，
所以是逐球传递——牛顿摆只飞出一个球。

**顺序冲量给出的正是"波传播"这一档**：δ=0 时 A-B 先接触、先解算，B 获得速度后
才与 C 相接，所以结果正确。这个"错误答案"是我的测试**故意让三球初始嵌入**才触发的，
而真实场景不会出现互相嵌入的初始状态。

于是有了两条工程措施，见第 6 节。

## 6. TOI 分段求解与初始状态校验

第 4.5 节说明了一个事实：**同一时刻存在多个接触时，求解器只能给出"整体同时变形"的解。**
而对硬物，正确行为是接触按时间先后逐个传递。要复现这一点，需要两条互补的措施。

### 6.1 措施一：拒绝初始互相嵌入

`PhysicsWorld.from_scene()` 会主动检查，发现超过 `overlap_tolerance`（默认 1 mm）
的初始穿透就抛异常，并列出所有违规的物体对：

```
发现 3 处初始穿透（仿真开始前物体就已经互相嵌入）：
  - 'ball_a' <-> 地面：初始穿透 300.000 mm
  - 地面 <-> 'ball_b'：初始穿透 300.000 mm
  - 'ball_a' <-> 'ball_b'：初始穿透 400.000 mm
```

判据直接复用窄相检测，所以"校验通过"和"求解器看到的接触集合"完全一致。
要临时放行（例如恢复一个已经贴合的堆叠）写 `"allow_initial_overlap": true`。

### 6.2 措施二：按预测接触时刻切分子步

窄相只看得到"此刻已穿透"的物体。如果一次检测只在一个时刻做，那么一个子步内
先后发生的多次碰撞会被当成"同时"。做法是在推进位置**之前**解析地算出下一次
接触的时刻，把子步切开，每段只解算此刻真正发生的接触：

```
阶段 A  先解算子步开始时已存在的接触（静置、堆叠）
阶段 B  循环：算最早 TOI → 推进到那一刻 → 只解算该时刻的接触
```

球-球的接触时刻是一元二次方程 `|d₀ + w·t| = R` 的较小正根，
球-地面退化为一元一次 `t = gap / (-v_z)`。

效果（`tests/test_toi_split.py`）：

| 指标 | 不分段 | 分段 |
|---|---:|---:|
| 单子步内链式碰撞终态 | 错误 | `[0, 0, 60]` 正确 |
| 最大穿透深度 | 150 mm | **0.000 mm** |
| `sim_spheres` 480 步耗时 | 0.230 s | 0.266 s（+16%） |

TOI 预测本身与解析解**逐位一致**（误差 0.0）。静置物体不触发事件
（实测平均 0.000 次/步），所以没有持续的额外开销。

### 6.3 这两条措施为什么够用

它们把"同时性"的问题转化成了"不要制造同时性"：

- 不互相嵌入 → 接触不会在第一步同时生效
- 按 TOI 切分 → 同一子步内的多次碰撞也会被还原成先后顺序

**代价是零**（TOI 只增加了 16%，而且消除了全部穿透），
不需要引入杨氏模量、不需要把步长降到 1e-6、也不需要换求解器框架。

### 6.4 仍然存在的限制

真实的"严格同时多体碰撞"（多个接触在同一瞬间以非零相对速度闭合）在刚性模型里
**本身是不适定的**——`[0,0,3]` 和 `[-1,2,2]` 都满足动量与能量守恒，选哪个取决于
材料刚度。本项目选择"波传播"这一档，因为它是硬物的真实行为，且与顺序冲量的
天然行为一致。

如果将来需要"软材料"那一档，唯一的途径是把接触改成弹簧-阻尼（软约束），
代价是步长要降到 `sqrt(m/k)` 量级——对钢的刚度约为 1e-6 s，比现在小三个数量级。
**这不是本项目应该付的代价。**

## 7. 踩坑记录

### 6.1 球会永远滚下去

第一版多球场景跑 5 秒后，有球的 `|v| = 1.002 m/s` 恒定不变。
诊断发现 `ω·r = 3.132×0.32 = 1.002`，即**完美纯滚动**。

这不是 bug：理想刚性球在水平面上纯滚动时接触点速度恰好为零，摩擦冲量为零，
所以没有任何力能让它减速。真实世界靠**滚动阻力**停下。

**处理**：加入指数阻尼 `v *= exp(-k·h)`。关键是只加角速度阻尼（1.0/s）
就能产生正确的滚动阻力——角速度衰减后纯滚动被破坏、开始打滑，
摩擦自然把平动也刹住。平动阻尼只保留很小的 0.05/s 模拟空气阻力。

### 6.2 球堆球是不稳定平衡，会被弹飞

最初让一个球从 1.55 m 落到另一个动球上，结果两球都弹出画面
（一个飞到 x=5.6）。原因是球-球接触点若略微偏心，法向不竖直，
会产生很强的切向冲量，把两个球"挤"开。

**处理**：把基球设为 `static`，并让下落球**精确对心**（偏移 0.000）。
此时法向严格为 +Z，没有任何切向分量，终态 `x = y = 0.0000`，完全稳定。

### 6.3 渲染脚本把旧视频当成了新结果

`_verify_video` 里"期望路径已存在就直接返回"的逻辑，导致第二次渲染时
读到上一次残留的 97 帧旧视频，而新生成的 `xxx0001-0049.mp4` 被留在原地。

**处理**：渲染前先 `os.remove` 掉同名旧文件。批量运行时尤其要注意这类
"残留文件被误认为产物"的问题。

### 6.4 视频动作只占前 1.3 秒

第一版设了 4.0 s / 97 帧，但数值检查显示 `max|v|` 在 **t=1.25 s** 就已经
精确为 0，后面 2.7 秒全是静止画面。

**处理**：先用数值检查定位静置时刻（不需要渲染），再定 `duration`。
最终取 2.0 s / 49 帧，动作占前 1.25 s，尾巴留 0.75 s 展示"已静置"。

**这条经验对后续所有出片都适用：先用数字确定时间轴，再渲染。**

## 9. 接口预留（为盒-盒准备）

`ContactManifold` 从第一天起就是**多点**结构：

```python
manifold = ContactManifold(
    body_a=0, body_b=3,
    points=[p1, p2, p3, p4],   # 盒-盒面贴面会有 4 个点
    friction=0.5, restitution=0.2,
)
```

求解器对每个点独立建立约束，不关心几何类型。因此下一步加盒碰撞，
**求解器一行都不用改**，只需要新增一个返回 `ContactManifold` 的窄相函数，
并在 `detect_contacts` 的分派里接上。

## 10. 已知限制

| 限制 | 说明 |
|---|---|
| 只有球体 | 盒/柱/胶囊会直接报错，不会静默跳过 |
| 单一静态平面 | 还没有盒子地面、容器、斜面 |
| 无暖启动 | 每次求解从零累积冲量；**堆叠前必须补上**（见第 4.4 节的收敛表） |
| 接触数多时收敛慢 | 8 个接触需要 30+ 次迭代，堆叠会塌陷 |
| 无睡眠机制 | 静置物体仍每步参与求解；当前规模无影响 |
| O(N²) 检测 | TOI 扫描与窄相都是 O(N²)，W3 替换为空间哈希 |
| 单点接触 | 球天然如此；盒-盒必须补流形裁剪 |
| 严格同时多体碰撞 | 刚性模型不适定，只表达"波传播"一档（第 6.4 节） |

## 11. 下一步

1. **暖启动（warm starting）**：跨帧缓存累积冲量。约 30 行，但能把堆叠所需迭代
   次数降 2–5 倍——**这是盒-盒堆叠的前置条件**，而且顺便能提供"算法加速"的实测数据
2. **盒-球**：球心到盒最近点，单点接触 → 验证盒子的姿态积分与转动惯量
3. **盒-盒 SAT**：15 条轴最小穿透 + 参考面/入射面裁剪 → 最多 4 个接触点。
   同一流形的 4 个点要**当成一组**求解，否则盒子四角互相打架，产生假旋转
4. **自碰撞**：接入全部刚体两两检测
5. **空间哈希宽阶段**：替换 O(N²)，保留暴力基线用于加速比测量

顺序的理由：先用盒-球把盒子的姿态积分与转动惯量验证干净，再上 SAT——
这样如果盒-盒出问题，范围就只剩窄相本身。而暖启动放在最前，是因为它不依赖
几何类型，且决定了后面堆叠能不能站住。
